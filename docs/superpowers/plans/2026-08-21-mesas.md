# Distribución de mesas y plano del salón — Plan de implementación

> **Para agentes ejecutores:** REQUIRED SUB-SKILL: usa `superpowers:subagent-driven-development` o `superpowers:executing-plans`. Los pasos usan casillas (`- [ ]`).

**Objetivo:** que el atelier reparta los grupos entre mesas, coloque el salón sobre un plano, y que la puerta cante el número de mesa al escanear el pase.

**Arquitectura:** módulo nuevo `src/modules/venue/` con la misma disposición que `src/modules/checkin/`, que se acaba de construir y sirve de plantilla exacta. Dos tablas nuevas y una columna `table_id` en `guest_groups`.

**Stack:** Next.js 16, React 19, Drizzle, Postgres 17, Vitest, Testing Library, Playwright, Tailwind con tokens propios.

**Spec:** `docs/superpowers/specs/2026-08-21-mesas-design.md`

## Restricciones globales

Idénticas a las del plan del check-in (`docs/superpowers/plans/2026-08-21-checkin-qr.md`, sección «Restricciones globales»). **Léelas ahí; aplican todas.** Resumen de las que más se olvidan:

- pnpm exclusivamente. Prefijo obligatorio en todo comando que toque la base:
  `DATABASE_URL=postgres://invite:invite@localhost:5434/invite SITE_URL=http://localhost:3000`
- `domain` puro; `application` nunca importa `infrastructure`; solo `src/app` los une.
- Ningún hexadecimal fuera de `src/shared/design/tokens.css`.
- Toda Server Action del panel abre con `await requireSession()`.
- Prohibido `any` y `@ts-ignore`. Errores con `Result`, nunca excepciones.
- `pnpm typecheck && pnpm lint && pnpm test` en verde antes de cada commit.

**Plantilla de referencia:** `src/modules/checkin/` tiene la forma exacta de dominio, puertos, casos de uso, adaptador Drizzle, acciones y barril. Cópiala en estructura, no en contenido.

## Task 5: Reparto — auto-asignación

**Archivos:** ampliar `src/modules/venue/domain/seating.ts` y su test

**Produce:** `autoAssign(tables, groups): { assignments: Array<{ groupId: string; tableId: string }>; unplaced: SeatedGroup[] }`

- [ ] **Paso 1: prueba que falla**

```ts
describe('autoAssign', () => {
  it('es determinista: dos ejecuciones dan el mismo resultado', () => {
    const a = autoAssign(tables, groups)
    const b = autoAssign(tables, groups)
    expect(a).toEqual(b)
  })

  it('nunca mueve lo que un humano colocó', () => {
    const r = autoAssign([table], [g('a', 4, 't1'), g('b', 2)])
    expect(r.assignments.map((x) => x.groupId)).not.toContain('a')
  })

  it('coloca primero los grupos grandes', () => {
    // Dos mesas de 4. Grupos de 4, 2 y 2. El de 4 tiene que entrar entero.
    const t4a = { ...table, id: 'A', label: 'Mesa A', capacity: 4 }
    const t4b = { ...table, id: 'B', label: 'Mesa B', capacity: 4 }
    const r = autoAssign([t4a, t4b], [g('p', 2), g('q', 2), g('grande', 4)])
    expect(r.unplaced).toHaveLength(0)
  })

  it('elige la mesa que deja el menor hueco', () => {
    const t6 = { ...table, id: 'A', label: 'Mesa A', capacity: 6 }
    const t4 = { ...table, id: 'B', label: 'Mesa B', capacity: 4 }
    const r = autoAssign([t6, t4], [g('x', 4)])
    expect(r.assignments[0]?.tableId).toBe('B')
  })

  it('informa de quien no cabe en ninguna, sin partirlo', () => {
    const r = autoAssign([{ ...table, capacity: 2 }], [g('x', 5)])
    expect(r.assignments).toHaveLength(0)
    expect(r.unplaced.map((u) => u.id)).toEqual(['x'])
  })

  it('sin mesas, todos quedan sin colocar', () => {
    expect(autoAssign([], [g('x', 2)]).unplaced).toHaveLength(1)
  })
})
```

- [ ] **Paso 2:** ejecutar → FALLA
- [ ] **Paso 3:** implementar con el algoritmo de la sección 3.1 del spec: solo grupos sin mesa, ordenados por cupos descendente y etiqueta ascendente a igualdad; a cada uno la mesa donde quepa entero dejando el menor hueco, desempatando por etiqueta. Sin `Math.random`, sin `Date.now`.
